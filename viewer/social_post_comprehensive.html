OpenClaw 記憶系統完整復盘

為乜要整呢個系統？

用 OpenClaw 幫我做嘢，最痛苦嘅唔係佢唔識答問題，而係：

佢用完就唔記得。

今個禮拜確認咗嘅方向，下個禮拜問佢，佢話冇印象。上個月做咗嘅決定，呢個月當新資訊處理。每個 session 之間，佢唔記得我係邊個，唔記得我做緊乜 project，唔記得我想要乜。

你可能會問：加長啲 system prompt、加多啲 memory 文件就得啦？

唔係。

當你嘅 agent 唔只一個，而係三個、四個、五個 — 每個都話自己係專家 — 你就會發現問題唔係 memory 容量，而係 memory 架構。

原本有乜問題？

1. 記憶碎片化

唔同嘅 task、唔同嘅 agent，個個都係孤島。Dev agent 做完嘢，QA agent 唔知做咗乜。每一個新 session，都係一張白紙。

2. 重要決定被忘記

幾個月前確認咗嘅項目方向，到下次傾 project plan 嘅時候，我又問多次。冇 trace，唔記得邊個做咗乜決定、幾時做嘅、點解咁樣做。

3. Handoff 混亂

一個 agent 做完嘢，下一個 agent 要由頭理解一次。啲資訊喺邊？點樣傳？冇標準流程，靠口耳相傳，一問就断。

4. 冇客觀事實

當多個 agent 對同一個事實有唔同理解，冇辦法知道邊個啱、幾時改咗、點解改咗。

我哋整咗乜？

過去幾日，由零開始，整咗一套三層嘅記憶系統。

第一層：底層資料庫

11 張 SQLite 表格，各司其職：

表格用途
`messages`Pipeline 行為記錄
`pipeline_runs`每一個工作流程的元數據
`stage_handoff_docs`Stage 之間的結構化交接文件
`agent_working_cache`Agent 工作狀態暫存
`stage_snapshot_cache`每個 Stage 完成時的 Snapshot
`shared_entity_memory`跨 agent 共享的實體資料
`approved_memory`已確認可重用的記憶

第二層：緩存架構

3 層 cache：

  • 代理工作緩存（AWC） — Agent 做緊嘢嘅時候，中間狀態先写入記憶，透過 debounce 批量 flush 到 DB
  • Stage Snapshot Cache（SSC） — 每個 Stage 完成時自動 snapshot
  • 共享實體記憶（SEM） — 跨 agent 共享的實體資料

第三層：運作規則

12 條 daily operating rules，核心係呢個信任層次（Trust-Ordered）：

1. MEMORY.md — 最高信任，官方事實
2. 結構化 handoff 文件 — 當前工作階段關鍵資訊
3. approved_memory — 已確認可重用的事實/決定
4. daily logs — 存檔/參考，無需第一時間讀取

任何 agent 讀取記憶，必須按呢個優先順序。只有主要助理可以更新 MEMORY.md，Worker agent 唔可以直接寫 official truth。

點整？— 分階段，數據驅動

唔係一次過整晒，而係分階段，每個 phase 有清晰嘅目標、驗收條件、做完先再做下一個：

Phase目標
Phase 1Pipeline + handoff + message log 基礎設施
Phase 2MEMORY.md 寫作紀律，變成工作流程規則
Phase 3`approved_memory` table + 讀寫函數
Phase 4`trust_lookup()` + `trust_startup_context()`
Phase 5`memory_changelog.md` — 追蹤記憶更正

每一個 component 落地之前，有單元測試。整完之后，有 integration test 行確保數據流向正確。

對我意味住乜？

  • 每次打開 chat，助理係陌生人
  • 兩週前確認嘅方向，下週變成未知
  • Worker agent 完成後 output 就消失

之後

  • 助理記得我係邊個、記得我嘅 project
  • 重要決定有 changelog，可以追蹤
  • Worker agent 之間有結構化 handoff

我幾時開始信任呢個系統？

係第一次我發現，記憶被靜靜雞改咗，但係我可以查到幾時改、點解改、邊個改。

Noise 消失咗，signal 留下嚟。

如果你都想整類似嘅系統？

你可能需要先問自己幾個問題：

  • 你有幾多個 agent？（呢個系統係為多 agent 場景設計）
  • 你嘅記憶痛點係乜？（係断片？係唔一致？係冇 trace？）
  • 你願唔願意每個 phase 之後停低評估，唔一次過整晒？

如果答案是「願意」，咁呢套嘢可能適合你。

如果答案係「想快啲落地」，建議由 MEMORY.md 寫作紀律開始，確立運作規則，再逐步加入其他 component。呢個系統可以慢慢建立起嚟。
