Swarm Before / After 對照圖
一眼睇清楚，Swarm 完成之前同之後有咩分別。重點唔係「多咗一個功能」，而係由單線人手協調，變成有 pipeline、有 handoff、有 observability 嘅多 agent delivery system。
BEFORE SWARM

有現成 protocol，但仲未有真正 swarm orchestration

1. 其實已經有固定 team protocol
SilverHand 會按 protocol 用 Handy / Scout / Wiser 分工，亦會做 pre-spawn check、session reuse、label discipline。
↓
2. 但 phase 推進仍然主要靠 SilverHand 手動協調
即使有 child session protocol，同一個 task 由 design → build → review → qa，仍然要人手判斷下一步同逐次派工。
↓
3. Handoff 有規矩，但未變成統一 pipeline artifact
已有規矩、已有 session discipline，但未必每個 phase 都有一致、可查、可追蹤嘅 structured pipeline handoff。
↓
4. 觀測能力未集中
你已有 session guard、kanban、status page，但未有一個真正以 pipeline / stage / agent execution 為中心嘅 swarm control surface。
AFTER SWARM

多 agent pipeline，自動 handoff + 可視化

1. Router 建立 pipeline
task 進入 spec / design / build / review / qa / ship 流程。
↓
2. Structured handoff
每一階段寫 facts、decisions、risks、open questions、next action。
↓
3. 下一個 agent 帶住上下文接手
唔再由零開始，handoff 可直接消化。
↓
4. Dashboard 可見
可見 active pipeline、agent status、elapsed time、最近 runs。
