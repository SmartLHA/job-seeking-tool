OpenClaw 智能助理 — 記憶系統升級分享

過去一段時間，用 AI 助手幫我做嘢，最大嘅痛苦係：

「用完就唔記得。」

今個禮拜同佢做咗嘢，下個禮拜佢唔記得。上個月做咗決定，呢個月佢當冇發生過。唔同嘅 session 之間，佢唔記得我係邊個，唔記得我做過乜，唔記得我想要乜。

你知唔知嗰種感覺？就係每次打開對話框，都係一張白紙。就算係同一個項目，上次嘅 context 全部蒸發咗。

呢個，就係我過去一段時間面對嘅記憶問題。

我哋點解要整呢個系統？

OpenClaw 係我嘅 AI 助手，幫我管理日常工作、coding、甚至決策。但係：

  • 記憶碎片化 — 唔同嘅 task、唔同嘅 agent，個個都係孤島
  • 重要決定被忘記 — 幾個月前確認咗嘅方向，再問佢就唔記得
  • handoff 混亂 — 個個 agent 做完嘢，下一個要由頭理解一次
  • 冇 trace — 佢幾個禮拜前嘅理解，同而家嘅唔一致，但係冇辦法知道幾時改咗

你可能覺得，加多用戶 prompt，加多 memory 文件就得。但係當你嘅 agent 多過一個，每個都話自己係專家，你就會知道，記憶管理唔係加幾行文字咁簡單。

你需要架構。

我哋整咗乜？

過去幾日，我哋重新架構咗成個記憶系統，唔係小修小補。

底層架構

  • 11 張 SQLite 資料庫表格，用於 pipeline、訊息、handoffs、cache
  • 3 層 cache 架構：代理工作緩存、stage snapshot cache、共享實體記憶
  • 自動 flush + debounce 機制，確保資料寫入唔會丢失
  • 5,000+ 行代碼，所有自動化測試皆通過（176 個測試）

記憶系統分層（Trust-Ordered）

1. MEMORY.md — 最高信任，官方事實 2. 結構化 handoff 文件 — 當前工作階段關鍵資訊 3. 已確認可重用的記憶 — 已批准的事實/決定 4. daily logs — 存檔/參考，無需第一時間讀取

所有記憶數據由用戶控制，儲存在本地。

運作規則

• 任何 agent 讀取記憶，必須按信任層次優先順序
• 只有主要助理可以更新 MEMORY.md
• Worker agent 唔可以直接寫 official truth
• 重要嘅記憶變更，必須留低 changelog

實際功能

• 每次新 session 開始，自動檢查所有記憶源是否可讀
• 任務切換時，自動 load 上個 stage 嘅結構化 handoff
• 重要決定被糾正時，寫入 changelog，唔會再靜靜雞消失
• 記憶大小控制 — 保持 MEMORY.md 短小，易於維護

對我意味着乜？

之前

  • 每次打開 chat，助理係陌生人
  • 兩週前確認嘅方向，下週變成未知
  • Worker agent output 做完就冇

之後

  • 記憶係持續嘅、有層次嘅、有 trace 嘅
  • 助理知道我係邊個，記得我嘅項目
  • 重要決定有 changelog，可以追蹤

你問我係幾時開始信任呢個系統？

係第一次我發現，記憶變更咗，但係我查得到幾時改、點解改、邊個改嗰刻。

訊息雜訊減少，核心訊號保留。
