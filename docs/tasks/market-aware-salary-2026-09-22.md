# Feature: market-aware salary (reminder + optional score effect) — 2026-09-22, REVISION 2

Mike: "build 薪資納入判斷 ... 讓評分和 A 到 F 等級參考市場位置，例如職位薪資落在市場後 25% 就提醒". Builds on docs/tasks/salary-benchmark-2026-09-22.md (src/job_hunt_salary_benchmark.py `summarise_histogram`, src/job_sources/adzuna_client.py histogram + cache + budget).
Revision 2 follows an adversarial design review (Opus, 2026-09-22) that rejected revision 1 (component 50% cap + grade cap + automatic cache-only use in pipelines) for: cache presence silently changing scores and decisions on later re-evaluation; day-rate salaries treated as annual (no periodicity field exists, `salary_is_annual` in normalize.py is never read); the −5 being a no-op above raw 100 (`min(raw,100)` in job_hunt_scoring.py ~63-71); triple counting with the base grade and the decision grade cap (job_hunt_qualitative.py ~48-86); JobAnalysis whitelist round-trip dropping unknown keys (job_hunt_storage.py `job_analysis_from_dict` ~176-230); presets changing the salary weight (salary_focused = 25); Adzuna terms vs the export zip. Standing rules: ranges not anchor points; caps only lower; score must stay comparable across jobs.

## What to build
### 1. Market position + sticky snapshot (the reminder) — ALWAYS ON
- Position bands are ranges, thresholds in src/job_hunt_config.py: `bottom` (< 25th percentile of the Adzuna histogram), `typical` (25-75), `top` (> 75), `unknown`. `unknown` when: no salary; salary is not clearly annual (guard: use the midpoint of salary_min/max ONLY if BOTH are >= 10000; anything lower is treated as day/hourly rate -> unknown; also unknown if the job's employment type says contract/temp/part-time when that field exists — find it; if there is no such field say so); sample total < 30 vacancies or fewer than 5 buckets. Pure function `classify_market_position(job_salary_min, job_salary_max, histogram_summary)`.
- Snapshot = dict {position, percentile, sample_total, histogram_date (fetched_at), query, salary_used, source:"adzuna", version:1}. STICKY: it is created ONLY by an explicit user action and is never recomputed, refreshed, dropped or read from cache by digest re-evaluation, batch, "Re-evaluate", `_ensure_*` page-view writers, or any pipeline. Re-evaluation must CARRY OVER the stored snapshot into the new JobAnalysis.
- Explicit action: on the job page salary panel, after a successful benchmark fetch, a button "Save market position to this job" -> new route `POST /job/{id}/market-position` (validate id with validate_job_id from src/job_hunt_export.py; 400/404/422, never 500; body carries nothing the server trusts: the server recomputes the position from the CACHED histogram for this job's cleaned title via a cache-only helper, using the SAME cache dir the panel writes (state_root/cache/adzuna_salary, thread it from config explicitly) and returns 409 "benchmark not fetched yet" if no fresh cache exists). A second click replaces the snapshot (explicit refresh) and records the new date. Add a "Remove market position" button (DELETE-like POST) to clear it.
- Storage: add an optional field to JobAnalysis (e.g. `market_snapshot: dict | None = None`) + `job_analysis_from_dict` + to_dict, with back-compat tests for old records without the field (compare tests/test_storage.py ~296-322 precedent); carry it through every place that rebuilds a JobAnalysis (grep for JobAnalysis( and dataclasses.replace and job_analysis_from_dict callers, including src/job_hunt_scheduler.py reevaluate_digest_jobs ~358-405 and src/job_hunt_evaluation.py, src/ui_handlers.py 614-645).
- Display: job page shows a badge "Market: bottom quarter (n=…, as of …, Adzuna)" (amber for bottom, neutral for typical/top; unknown = nothing) near the header tags and in the salary panel; a "Below market" note in the verdict area with the reason; old jobs without snapshot render unchanged. It must NOT enter `risk_flags`, `critical_risk_codes` (src/job_hunt_config.py ~79-87) or blockers, and must not change match_score, decision or grade when the score effect (below) is off. Test that.
- Export: exclude the snapshot and any market/Adzuna wording from `analysis.md` and `job.json` in the export zip (src/job_hunt_export.py) — Adzuna terms allow personal research only; the zip goes to employers. Add a test asserting absence.
- Update the now-false comments: src/job_hunt_salary_benchmark.py:1-4, src/ui_handlers.py ~749 ("Advisory only: never touches scoring..."), src/job_sources/adzuna_client.py ~100-101, and docs/tasks/salary-benchmark-2026-09-22.md (dated note).

### 2. Optional score effect — PRESET OFF
- `market_score_effect_enabled()` function in src/job_hunt_config.py returning a module-level setting `MARKET_SCORE_EFFECT = False` (read through the function so tests can monkeypatch; default False).
- When enabled AND a stored snapshot says `bottom`: after `score_job` computes the clamped final `match_score`, deduct a FIXED absolute 5 points (independent of scoring preset weights), floor at 0, recorded as its own visible breakdown line/reason "Market adjustment: −5 (bottom quarter of market, Adzuna n=…, date)" — never inside the salary component. Decision is then derived from the adjusted score by the normal thresholds (Apply>=80, Review>=65); grade derives from the adjusted score/decision naturally — NO separate grade cap (avoids double counting). No bonus for top/typical. Add a `market_adjustment` numeric field to the analysis (or inside the breakdown structure) so the effect is auditable, and list in the UI that the score includes it. Explain in the report every threshold this can cross (Apply->Review for scores in [80,85), Review->Skip for [65,70), digest_threshold 70 boundary [70,75)) and add tests for each boundary and for raw >100 jobs (adjustment applied after clamp).
- Must apply identically on all evaluation paths (single submit, /evaluate, re-evaluate, batch, digest reevaluate_digest_jobs) via ONE helper called after scoring; find all paths (src/job_hunt_evaluation.py, src/job_hunt_orchestrator.py, src/job_hunt_scheduler.py, src/ui_handlers.py `_run_intake_evaluation`). Uses ONLY the stored snapshot, never the network or cache.
- With the switch off (default): identical `match_score`/`decision`/grade to before on a golden fixture set (run existing scoring/decision/evaluation tests + a new golden test); do not claim byte-identical stored files.
