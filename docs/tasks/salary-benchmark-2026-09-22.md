(hierarchy, NOT `where`), `content-type=application/json`. Response `{"histogram": {"<lower bound of salary range>": "<vacancy count as string>"}}`; key order not guaranteed. (https://developer.adzuna.com/docs/histogram)
- History (average salary per month): `GET /v1/api/jobs/gb/history` returns `{"month": {"YYYY-MM": <float>}}`; whether `what` is accepted is UNVERIFIED -> NOT used in this version. (https://developer.adzuna.com/docs/historical)
- Limits: default 25 hits/min, 250/day, 1000/week, 2500/month. Terms: personal research use is permitted; publishing aggregates needs written consent; salary data must acknowledge Adzuna as the source; stored data must be removable. (https://developer.adzuna.com/docs/terms_of_service)
- UNVERIFIED: histogram params beyond what/locationN; whether predicted salaries are included; salary_is_predicted value type. State this in the UI caveat ("advertised salaries, may include estimates").
- Existing client `src/job_sources/adzuna_client.py` `fetch_adzuna_jobs` returns [] on any failure (cannot tell failure from no data), logs exception text (which may contain the URL with app_key!), writes raw responses to data/raw/adzuna/. ## Smallest useful flow
On the job detail page, a "Salary benchmark" panel with a button "Check market salary" (lazy — never fetch during page render). It calls new `GET /job/{id}/salary-benchmark` which returns JSON; the panel shows: the job title query used, sample size (sum of counts), the bucket range containing the median, the position of THIS job's advertised salary (midpoint of salary_min/max if present, else "no salary advertised") as a percentile of the histogram, and the position of Mike's `salary_floor_gbp`, plus "as of <date>", "Source: Adzuna" with a link to https://www.adzuna.co.uk, and the caveat text. If there is no data, say "No Adzuna data for this title" (distinct from an error). Advisory only: it must NOT change scoring, decision or grade.

## Requirements
1. New module function in src/job_sources/adzuna_client.py: `fetch_adzuna_salary_histogram(what, *, location=None)` returning a small typed result (dataclass or dict with `status` in {"ok","no_data","error","unavailable"}, `buckets` sorted list of (lower_bound:int, count:int), `total`, `fetched_at`, `error` message that NEVER contains the URL, app_id or app_key). `unavailable` = missing credentials (no HTTP call). Handle 429 and timeouts (10s) as `error`. Do not write raw histogram responses to data/raw. Never log a URL with params; scrub exceptions (log only the exception class and status code).
2. Cache: file cache under data/state/cache/adzuna_salary/ (gitignored path; check .gitignore covers data/state) keyed by sha256 of (normalised what, location), TTL 24h, only successful/no_data results cached. Plus a persisted daily-call counter; refuse further HTTP calls at 200/day with status "error" and a message "daily Adzuna budget reached" (Adzuna cap is 250/day). Clock and cache dir injectable for tests.
3. Query builder: `what` = job title cleaned (strip seniority/contract noise like "(Contract)", "- London", trailing company text; keep it simple, pure function with tests). Nationwide UK (no location) in v1; location left as a parameter for later.
   - Seniority words (senior, lead, principal, junior, head of) are kept on purpose (2026-09-22); only contract/location/company/salary noise is stripped.
4. Route: `GET /job/{id}/salary-benchmark` in ui_routes.py + handler in ui_handlers.py. Validate job id with `^[A-Za-z0-9._-]+$` (400 otherwise) BEFORE any file access; 404 if job unknown; JSON response with computed stats. Statistics computed in a pure function `summarise_histogram(buckets, job_salary, floor)` (median bucket, percentile rank, total) with unit tests including empty, single bucket, unsorted keys, string counts.
5. UI: panel in src/ui_render.py job page (fetch + loading + error states, escape all text, inline message not alert()); keep ui_render.py free of giant `+` chains.
6. No change to scoring or the profile schema.
