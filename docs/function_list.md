## Implemented HTTP surface

- Shell: `GET /` (single-page landing shell; `?tab=` selects the active tab, default `search`).
- Discovery: `GET /search/{source}`, `POST /select/{source}`, `GET /search/{source}/more` (generic load-more for every source — Reed, Adzuna, LinkedIn; `/search/reed/more` still works via the same regex/back-compat shim), `GET /sources`.
- Pagination contract: `handle_source_search_more` normalises the query via the source's own normaliser, re-runs its `search_handler` one page deep, and renders bare cards through `JobSource.render_cards_fragment(results, *, skip, nonce)` with ids offset by `skip`. `_take_skip_param_keys` resolves camelCase (`resultsToTake`/`resultsSkip`) vs snake_case (`results_to_take`/`results_skip`) param naming. Button/loader HTML come from `src/job_sources/_multiselect.py` (`more_button_html`, `MULTISELECT_JS`/`jstLoadMore`, targeting `jst-cards-container`/`jst-more-wrap`). Adzuna pages by URL page number (`skip//take+1`); LinkedIn by `start` offset (part of its cache key).
- Review/evaluation: `POST /prefill`, `POST /job-submit`, `POST /evaluate`, `GET /job/<id>`, `GET /job/<id>/evaluate-form` (bookmark→evaluate: reload a saved job into the Evaluate form, preserving job_id), `GET /job/<id>/explain`, `POST /job/<id>/decision`.
- Document and profile actions: `POST /tailor`, `POST /cover-letter`, `POST /job/<id>/add-gap-skills`, `POST /job/<id>/ai-review-cv`, `POST /job/<id>/ats-recheck`, `GET /profile`, `POST /profile/parse-cv`, `POST /profile/save`.
- Board and batch flow: `GET /jobs`, `GET /board`, `GET /board/view`, `POST /jobs/save`, `POST /jobs/batch-evaluate`, `GET /review-queue`.
- Not-interested triage (2026-07-02): `POST /jobs/not-interested` (hide, idempotent; body `{jobs:[{source, source_job_id, title, company}]}`; returns per-entry `keys` + `total_hidden`), `POST /jobs/not-interested/undo` (body `{keys:[...]}`; shared by the undo toast and the overlay Unhide), `GET /jobs/not-interested` (full list, newest first, for the Hidden jobs overlay). Search + `/more` responses filter through the store; `/more` JSON adds `visible_count` + `hidden_count` while `count`/`has_more`/next skip stay on the raw page.
- Outcomes: `POST /outcome` (form: `job_id`, `status`, `notes`, optional `embed=1` to stay in review-queue iframe mode; status choices offered in the UI are pre-filtered via `allowed_next_statuses`; success/error re-renders the job page with inline feedback in the Outcome card).
- Saved searches (Digest D1): `GET /saved-searches`, `POST /saved-searches`, `POST /saved-searches/{id}/delete`, `POST /saved-searches/{id}/toggle`.
- Digest (D2): `GET /digest/count` (sidebar badge; `{unseen: N}`).
- Digest pipeline (D3): `POST /saved-searches/{id}/run-now` (sync run, returns `DigestRunResult`), `GET /scheduler/status` (static until D5).
- Digest feed (D4): `GET /digest` (filtered feed page), `POST /digest/mark-seen` (`{all:true}` xor `{job_ids:[...]}`).
- Digest scheduler/worker (D5/D6): `GET /scheduler/status` (live daemon status), `POST /digest/run-llm-batch` (manual paced drain), `GET /digest/llm-queue` (queue counts + RPD used).
- Re-evaluate seen jobs (OQ-2): `POST /digest/reevaluate` (sync re-score of every digest row vs current profile/threshold; returns `ReevalResult` JSON — examined/rescored/resurfaced/llm_requeued/dequeued/missing/errored; no Gemini call, crossed-up jobs only queued).
- LinkedIn (P5-2): `GET /search/linkedin`, `POST /select/linkedin` (registered via `_register()` import-time side effect; requires `from src.job_sources import linkedin_source` in `ui_routes.py` and `ENABLED_SOURCES` entry to appear in UI).
- Qualitative assessment (career-ops slice 1, 2026-07-08): `POST /job/{id}/qualitative-assess` — idempotent (an atomic CAS claim in `qualitative_index` returns the in-flight status instead of double-calling Gemini; `force` only honoured when no claim is `running`, archives the prior assessment by prompt_version/created_at). Also renders the A-F grade badge (slice 2) alongside the panel.
- Batch qualitative assessment (career-ops slice 3, 2026-07-09): `POST /jobs/batch-assess` (enqueues selected review-queue job ids; rejects duplicate enqueue within a batch), `GET /batch/{batch_id}` (server-rendered progress: N done / M total, per-job status, error text), `POST /batch/{batch_id}/cancel` (pending rows only — a running job finishes its in-flight Gemini call and checks cancellation again before persisting the result, so cancellation is never instant for an in-flight row).

## Important contracts

- Confidence is categorical: `low`, `medium`, or `high`, not a probability.
- The visible score breakdown has six buckets; its skills bucket contains two separately weighted components, so scoring has seven weights in total.
- `source_ref` retains an advert URL where available. Job pages render it as **View original posting / Apply**.
- Tailoring and cover-letter generation are local, decision-gated actions. Neither submits an application.
- F1 v2 re-check (`POST /job/<id>/ats-recheck`) re-scores the keyword match against the latest saved **tailored** CV and shows `was X% → now Y%`. It overwrites `keyword_match_rate` (the verdict card moves too — intended for MVP) while preserving the master baseline in `keyword_match_baseline_rate`; the AJAX panel is rendered through the same view-model path as a full reload. No tailored CV → 422; an empty tailored file → 422 (never overwrites a valid rate).
- Daily Digest **D1–D6 are complete** (Saved Searches, schema/dedup, pipeline + Run-now, filterable feed + badge, automatic daily scheduler daemon, and the paced rate-limited Gemini worker). Both daemons auto-start gated by the profile toggles (and a Gemini key for the worker). Gap Coach, broader source coverage, and DOCX/PDF output remain backlog.
- Career-ops absorption **slices 1-3 are complete** (2026-07-08/09): qualitative assessment layer, A-F grade badge, persisted batch queue. The qualitative layer and the grade are **advisory/presentation only** — they never change `match_score` or the Apply/Review/Skip decision; the grade is a deterministic band over the existing 0-100 score, capped (never raised) by the effective decision and by qualitative culture/red-flags evidence, always shown as base→capped+reason when they differ. Comp-vs-market dimension excluded (no market-data source); bulk URL/JD paste batch input deferred (v1 = review-queue selection only).
